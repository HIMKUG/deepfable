模型默认会收敛到保险、通用的界面：Inter 字体、白底、紫色渐变、等距的圆角卡片、每节淡入。要得到"设计过"的结果，必须在少数几个维度上做**明确承诺**，并在交付前**真的看一眼渲染结果**。

## 0. 先定方向

写 CSS 前，用一两句话定下：气质、字体、主色、唯一一个动效时刻。方向必须来自主题——运维控制台、园艺规划、金融仪表盘不该长成同一个 starter template。

如果 brief 没说清主题，先提出一个具体主题、受众和页面的主任务，再设计。

判断标准：这段话如果换个产品也成立，就是没定方向。

首屏放主题里最有代表性的东西：一句话、一张图、一个动效、一个可交互演示。不要默认"大数字 + 小标签 + 渐变装饰"。字体本身可以作为视觉元素，不是中性的内容容器。

## 1. 四个维度

### 字体

- 最快暴露"模板感"的维度。避开 Inter、Roboto、Open Sans、Lato、system-ui。
- 最多两族，且差异明显：一个有个性的展示字体 + 一个干净的技术无衬线；数据多时加一个等宽字体。
- 权重拉开：200 vs 800，不要 400 vs 600。字号跳跃约 3 倍，不要 1.5 倍。
- 建立明确字号阶梯（如 12 / 14 / 16 / 24 / 40 / 64），每一级有用途，不凭感觉挑字号。
- 按气质选：代码感 JetBrains Mono / Space Grotesk；编辑感 Fraunces / Playfair Display；个性 Bricolage Grotesque / Clash Display；技术感 IBM Plex 系列。
- 正文行宽小于 80 字符；衬线正文行高略大于无衬线。

### 颜色

- 用 CSS 变量集中管理，4–6 个具名 hex。
- 一个主导色 + 一个锐利强调色，胜过均匀分布的"保守配色"。
- 强调色要有职责：品牌色 + ok / attention / alert 各一个语义色，不兼职装饰。
- 从真实参照取色（IDE 主题、印刷品、材料色），不从通用色轮取。
- 避开：紫白渐变、Bootstrap/Tailwind 默认蓝、奶油底 + 陶土红（#D97757 一类）、近黑 #0B0B0B / #111 冒充纯黑。

### 动效

- 一个编排好的时刻胜过满屏微交互。页面加载时用 `animation-delay` 做错落揭示。
- 纯 HTML 用 CSS；React 且已依赖 Motion 时才用库。
- 必须尊重 `prefers-reduced-motion`。
- 避免：每节 fade-and-slide-up、每张卡片 hover 位移、无意义的视差。

### 背景

- 要氛围，不要平涂。叠加微弱渐变、细纹理、网格，或与主题相关的光晕。
- 层次感来自 2–3 个低对比层，不是一个大渐变。

## 2. 反模板清单

以下特征本身不算错，但**无论什么主题都出现**时就是默认值，不是选择：

1. 奶油底（约 #F4F1EA）+ 高对比衬线标题 + 陶土色强调。
2. 近黑底 + 单一荧光绿或朱红强调。
3. 报纸版式：细线分隔、零圆角、密集多栏。
4. SaaS 卡片套件：所有内容切成同款圆角卡片，所有层级同一个圆角，每张卡同一个柔和阴影，渐变当装饰。
5. 模板化装饰：每个标题上方一个全大写、加字距的小标签；元信息用中点连接（A · B · C）；"词 — 片段"式标签；小数据用等宽字体；链接和按钮后面加"→"。

如果 brief 明确要求其中某种风格，照做。brief 没指定的维度，不要浪费在这些默认值上。

## 3. 结构即信息

- 编号（01 / 02 / 03）只在内容真是序列时使用——步骤、时间线、优先级。否则是假结构。
- 不要给标题里的某一个词单独换色、加粗或斜体来"强调"。
- 不要用全大写做标签。
- 不要在每个标题上方加一个没有信息量的 eyebrow 标签。
- 分隔线、边框、编号、标签必须编码信息；纯装饰的删掉。

## 4. 克制

- 只让一个元素成为记忆点，其余保持安静、有纪律。
- 香奈儿规则：出门前照镜子，去掉一件配饰。交付前删掉一个装饰。
- 质量底线，不用声明：移动端可用、键盘焦点可见、对比度达标、尊重 reduced motion、配色和谐。
- 自评时截图看，不凭代码想象。一张图胜过一千个 token。

## 5. 信息架构

- 导航按用户要做的事分组（监控 / 审核 / 管理），不按页面清单平铺。
- 首屏要能回答："现在是否正常，有什么需要我处理？"再进入详情。
- 标签用用户语言，不用内部术语。
- 空状态要教下一步动作。

## 6. 两遍流程

**第一遍：定 token**

- 颜色：4–6 个具名 hex，写清角色。
- 字体：族名、角色、权重、字号阶梯。
- 布局：一句话概念 + ASCII 线框；写明对齐方式（左对齐 / 居中 / 两端）。
- 原则：这个页面为什么只属于这个 brief，三条以内。

**第二遍：对照 brief 审查**

如果某一部分换成任何同类产品也成立，就是默认值，改掉，并说明改了什么、为什么。确认相对独特后再写代码。

**构建时**

- 先改设计系统（颜色、字号、间距、卡片/行/按钮/徽章），再改单页；共享类名改一次，全站一起变。
- 注意 CSS 选择器特异性；`.section` 和 `.cta` 这类易互相抵消，间距尤其容易出问题。
- 重设计改 markup 时保留 `data-testid`、ARIA 角色和断言文本，测试才不会白挂。
- 本地或隐私敏感项目自托管字体（woff2），不要运行时请求 CDN。

## 7. 视觉验证

测试通过不代表界面对。缩略图没约束、进度条溢出、文字被侧栏裁切，测试都看不见。

- 用种子数据跑起应用，截取关键路由，实际看图。
- 无头浏览器示例：

```
chrome --headless=new --disable-gpu --hide-scrollbars \
  --force-device-scale-factor=2 --window-size=1440,900 \
  --virtual-time-budget=6000 --screenshot=out.png \
  "http://localhost:<port>/<route>"
```

- 检查：横向溢出、文字裁切、图片比例、对比度、焦点态、空状态、移动端断点。
- 报告"页面实际长什么样"，不只报告"构建通过"。

## 8. DeepSeek 高发问题

| 问题 | 修正 |
|---|---|
| 紫色渐变 + 白底 | 从主题取主色，建立 4–6 色变量 |
| Inter 一统到底 | 换展示字体，权重拉到 200/800 |
| 所有卡片同款圆角同款阴影 | 按层级分三档圆角与阴影，或去掉阴影改用边框 |
| emoji 当图标 | 用一套线性图标或纯文字 |
| 通用 hero：大数字 + 小标签 + 渐变装饰 | 换成主题里最有代表性的东西：一句话、一张图、一个可交互演示 |
| 每节淡入 + 每卡悬停 | 只保留一个加载编排 |
| 全大写小标签 + 中点元信息 | 删掉装饰标签，元信息用普通句子 |

## 9. 交付前清单

- [ ] 一句话方向写得出，且换产品不成立
- [ ] 字体不是 Inter/Roboto/Open Sans/Lato/system-ui
- [ ] 颜色有主导色 + 有职责的强调色
- [ ] 只有一个动效时刻，且尊重 reduced motion
- [ ] 编号只用在真序列上
- [ ] 没有同款卡片套件和装饰性渐变
- [ ] 键盘焦点可见，对比度达标
- [ ] 截图看过，无溢出、裁切、错位

## 10. 专用视觉技能

任务超出"网页 UI 的通用审美"时，加载对应 skill，不要用本文件的规则硬套：

| 任务 | 加载 | 说明 |
|---|---|---|
| 海报、静态艺术、PNG/PDF 视觉 | `canvas-design` | 先写设计哲学，再做画布；内置字体 |
| p5.js 生成艺术、流场、粒子 | `algorithmic-art` | 先写算法哲学，再实现交互式作品 |
| 给幻灯片/文档/网页套统一主题 | `theme-factory` | 10 套主题；先展示 showcase，再让用户选 |
| 复杂 React/Tailwind/shadcn 页面 | `web-artifacts-builder` | 初始化、开发、打包成单 HTML |
| 本地 Web 应用测试（用户明确要求时） | `webapp-testing` | Playwright；先跑 `with_server.py --help`；默认不主动测试 |
| Anthropic 品牌物料 | `brand-guidelines` | 只在明确要求 Anthropic 品牌时用 |
| Slack 动画 GIF | `slack-gif-creator` | 尺寸/体积约束与帧合成 |

加载后以该 skill 的 `SKILL.md` 为准；本文件的四维、反模板清单和截图验证仍然适用。
