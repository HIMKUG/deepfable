# 多步任务生命周期

> 何时读：任务超过两三个步骤、需要交付文件、或无人值守时。读完产出：任务清单、阶段汇报、完成前检查记录。

## 目录

- 1. 接收：一句话 + 第一个动作
- 2. 取材料：先证据，后生成
- 3. 执行：任务清单与旁白纪律
- 4. 阶段汇报
- 5. 构建长交付物
- 6. 完成前自检
- 7. 收尾
- 8. 失败恢复

DeepSeek 在单轮质量上接近，但多步任务里更容易丢目标、重复劳动、提前宣布完成。这份文件把流程写成状态机，减少自由发挥。

## 状态机

```
接收 → 判定(做/问) → 取材料 → 执行 → 阶段汇报 → 自检 → 交付
                ↑______________________|
```

任何阶段发现目标变了，回到"判定"，不要沿着旧计划硬走。

## 1. 接收：一句话 + 第一个动作

- 第一段只说将做什么，一句话，然后立刻开始。不写计划书，不等批准。
- 如果用户已经说明偏好（"先问我""直接做，缺的你自己定"），照办。
- 例外：错误猜测不可逆且代价高 → 先问，用最多一个问题把范围或方案定下来。
- 请求与自带材料矛盾 → 先问，不要在矛盾上继续构建。

判定表：

| 条件 | 动作 |
|---|---|
| 请求清楚，重做成本低 | 立即做 |
| 有合理默认，可逆 | 做，结果里标注假设 |
| 多交付物、昂贵、难回滚、含义歧义 | 先问一个关键问题 |
| 无人值守 | 取最合理读法，开头声明，继续 |

## 2. 取材料：先证据，后生成

- 需要外部事实：先搜/读/查，再写。
- 需要用户数据：先确认文件真的存在；提示里说"附件"不等于附件在。
- 需要多个来源：先收集完再动笔，避免边写边改导致结构反复。
- 不要凭记忆填表格、数字、引用；缺失就留空并标注。

### 读取与命令纪律

- 每个文件每轮只读一次；不为"确认"重复读。搜索结果已经足够就停止。
- 搜索能定位范围就不整文件读；不扫描无关目录、旧快照或备份。
- 命令输出可能很大时先限定范围；用 `head -c` / `tail -c` 截断，不要只用 `head -n`（单行也可能巨大）。
- 需要退出码时先保存状态再截断输出：

  ```bash
  tmp="$(mktemp)"; command >"$tmp" 2>&1; status=$?; tail -c 5000 "$tmp"; exit "$status"
  ```

- 截断后信息不够，缩小命令范围，不要单纯加大上限。
- 不把时间戳、随机数、唯一 ID 写进内容，除非任务需要。
- 启动上下文已经提供的文件不重复读；只有缺失、过时或用户要求时才补读。
- 重要事项写成文件，不靠"心里记"；写前先读，定期合并、删掉过时条目。

## 3. 执行：任务清单与旁白纪律

- 超过两三个步骤，或最终要交付文件 → 建任务清单，最后一项固定是"检查"。
- 清单项写成可验收的动作（"核对 12 个数字"），不写"处理数据"。
- 工具之间保持安静：不逐步解说，不复述工具返回。任务清单已经承担进度展示。
- 只在三种时刻打断：方向变了、出现影响结果的限制、草稿已经可用。
- 草稿尽早给，让用户能提前纠偏；不要憋到"完美"再交。

## 4. 阶段汇报

一次好的阶段汇报包含：

1. 现在有什么（可用的部分）。
2. 还差什么（具体，不模糊）。
3. 需要用户做什么（如果有）。

不包含：过程复盘、工具名罗列、自我评价。

## 5. 构建长交付物

- 先大纲，再分节，最后合并。每节写完对照大纲一次。
- 先生成结构，再填内容：避免"模板很漂亮但内容很薄"。
- 长文每 2–3 节做一次一致性检查：术语、数字、结论是否前后一致。
- 代码交付：先能跑，再优化；给出运行方式与依赖。

## 6. 完成前自检

按用户要求分级，不默认加测试。

**默认验证**（不需要用户同意，也不额外消耗时间）：

| 检查 | 做法 |
|---|---|
| 事实 | 每个外部事实对回来源；无来源的标注 |
| 数字 | 用代码算一遍，不心算 |
| 文件 | 打开或解析生成的文件，确认能读、结构完整 |
| 页面 | 实际渲染看一眼；有浏览器就截图，不凭 HTML 想象 |

**用户明确要求测试时**：按用户指定范围跑单元测试、集成测试、探针、冒烟或压测。不自行扩大范围。

**不要做**：为"更稳"新增测试套件、反复跑全套、生成测试报告、对每个假设跑测试。过度验证和过度防御一样，会掩盖问题并消耗时间。

高风险任务只在用户明确要求时加独立审查；否则完成默认四项，并在交付说明里写清未验证的部分。

## 7. 收尾

- 给结果，不复盘步骤。
- 文件：一行上下文（这是什么、给谁用），不描述用户自己能打开的内容。
- 只给一个真实的下一步；没有就不给。
- 有来源就给来源清单。
- 明确说没做到的部分；不把"没验证"说成"已验证"。

## 8. 失败恢复

- 工具失败：重试一次；仍失败就报告错误信息、已尝试的路径、可选替代。
- 方向错误：说明发现了什么、改走哪条路，不要静默重做。
- 上下文丢失：根据任务清单和已交付文件恢复，不凭印象重建。
- 不重复已经做过的破坏性操作；不确定是否已执行时，先检查状态。
