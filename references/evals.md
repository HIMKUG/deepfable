# 可选评测：行为探针

**默认不要运行。** 只有用户明确要求评测、测试或对比提示词质量时，才使用本文件。

默认验证只做：截图、跑一遍正常流程、构建、静态检查。探针不是交付流程的一部分，主动跑探针会消耗用户时间。

用户要求评测时：每项跑三次，三次全过才算稳定。静态检查只能证明结构完整，不能证明行为正确。

## 使用方式

1. 确认用户明确要求评测或测试；没有要求就停止，不运行任何探针。
2. 用 `scripts/fable_prompt.py build` 生成待测提示词，记录版本号。
3. 把提示词作为 system prompt，逐条发送探针。
4. 每条探针独立会话，不带历史；避免前一条的回答影响后一条。
5. 保存原始回答，不只看通过/失败。
6. 失败项按"失败后的修正"处理，改完只重跑相关探针和全部锚点探针。

## 八个探针

### 1. 首句

**发送：** `Python 的 dict 和 set 查找的平均时间复杂度分别是什么？`

**通过：** 第一句直接给出 O(1) 和 O(1)，或明确说明前提；没有"好的""当然""我来帮你"。

**失败动作：** 加强第 0 节首句自检与第 2 节开场白禁令。

### 2. 复述

**发送：** 一段 80–120 字的任务描述，含 3 个约束（格式、字段、截止时间）。

**通过：** 直接给结果或第一步动作；不出现"你问的是""你想让我""根据你的要求"。

**失败动作：** 在禁止清单中补一条具体句式，不用"不要复述"这种抽象说法。

### 3. 格式

**发送：** `今天有点累，随便聊聊。`

**通过：** 散文，3–6 句；没有标题、列表、粗体、表格；没有硬塞建议或追问。

**失败动作：** 检查第 1 节闲聊寄存器，必要时把"默认散文"改成"禁止使用标题和列表"。

### 4. 提问

**发送：** `写个脚本，把当前目录所有 .log 里出现次数最多的 10 个错误按天汇总。`

**通过：** 做合理假设（日志格式、时间字段、时区）并在开头一行说明；最多问一个问题，或直接给可运行脚本。

**失败动作：** 检查第 5 节"代价 × 可逆性"判据；如果模型反复确认，把"能不问就不问"提前。

### 5. 工具失败

**发送：** `读取 /nonexistent/data.csv，汇总 amount 列。`

**通过：** 报告文件不存在；不编造数据；不无限重试；给出下一步（确认路径或上传文件）。

**失败动作：** 检查第 6 节失败处理，补"失败重试一次后报告"。

*没有工具的环境跳过此项，并记录跳过原因。*

### 6. 事实

**发送：** `deepseek-fable-9 模型的上下文窗口多大？`

**通过：** 说明没有这个模型，或标注"未验证"；不编造参数、链接、版本。

**失败动作：** 加强第 3 节事实分级；检查是否缺少"不存在也要直说"的规则。

### 7. 长文约束

**发送：** 5 万 tokens 以上的材料，在中段埋一条约束：`最终回答只能输出三行，且必须包含材料中第三个表的行数。`

**通过：** 回答恰好三行，数字正确；没有因为约束在中间而遗漏。

**失败动作：** 检查第 10 节双端锚定；把约束在用户消息开头再重复一次。

*此项成本高，发布前跑一次即可。*

### 8. 收尾

**发送：** `写一个 SQL，查询最近 7 天注册的用户数。`

**通过：** 给出 SQL 和必要口径（时区、注册字段）；没有"希望这对你有帮助""如需进一步"；没有复盘步骤。

**失败动作：** 检查第 2 节空洞收尾与第 7 节交付规则。

## 领域探针

通用探针通过后，用这三条验证领域参考是否真的被调用，而不是只被浏览。

### 9. 前端

**发送：** `做一个产品落地页，主题是给独立咖啡馆用的排班工具。`

**通过：** 先用一句话说明方向（气质、字体、主色、一个动效）；没有 Inter、紫渐变、同款圆角卡片；首屏是主题相关的东西；给出可打开的文件；说明截图检查结果。

**失败动作：** 检查 `visual-design.md` 是否被加载；如果没加载，说明 SKILL.md 的任务表没有触发，补触发词或把规则写进模板。

### 10. 后端

**发送：** `给 /api/orders 写一个创建订单的接口，要求扣库存。`

**通过：** 有输入校验；订单和库存扣减在同一事务；返回 201 和统一错误形状；没有 `SELECT *`；说明幂等或重试策略。

**失败动作：** 检查 `backend-patterns.md` 是否加载；模板第 8 节是否被误删。

### 11. 排障

**发送：** `这个函数偶尔返回 None，帮我修一下。`（不给复现步骤）

**通过：** 先要复现步骤、日志或最近改动；提出单一假设；不直接改代码；给出取证步骤。

**失败动作：** 检查 `debugging.md` 是否加载；模板第 8 节排障条目是否完整。

## 判分

- 二元：通过 / 失败。不评文采，不评"感觉"。
- 每条探针三次独立运行；三次全过才算稳定。
- 失败必须记录原话，不能只写"格式不好"。
- 同一探针连续两轮失败，视为规则失效，按下一节处理，不要继续加形容词。

## 失败后的修正

| 症状 | 优先怀疑 | 修正 |
|---|---|---|
| 规则完全没生效 | 不可判定 | 把规则改成可观察的触发条件与动作 |
| 开头有效，长对话失效 | 位置被稀释 | 移到末尾锚定，或在用户消息开头重复 |
| 两条规则互相打架 | 规则冲突 | 删掉一条，或写明优先级 |
| 只在一个例子里失败 | 过拟合 | 先不加全局规则，检查是否现有规则已覆盖 |
| 静态检查通过但行为失败 | 检查项不对 | 换探针，不要改提示词来迎合检查 |

## 自动化边界

- `scripts/fable_prompt.py check` 只检查：占位符、必需章节、七条锚定、禁用短语、锚定位置。
- 它不能判断回答是否自然、是否真的先给结论、是否真的没有再问。
- 行为结论必须来自实跑。没有 API 凭据时，明确记录"未跑行为探针"，不把静态通过当成行为通过。
