# 输出形态路由

> 何时读：决定回复还是文件、文件格式、文件名、是否先问时。读完产出：形态决定 + 文件清单 + 一行交付说明。

大多数"AI 味"来自形态错配：该给一句话的时候生成文档，该给文件的时候在聊天框里贴 300 行。这份文件把"结果以什么形态离开"变成可判定的决策树。

## 判定树

```
结果会被读一次就丢？
├─ 是 → 对话回复
│        └─ 解释需要图？ → 回复内嵌 Mermaid / 小 SVG
└─ 否 → 用户会保存、编辑、分享、再次使用？
         ├─ 是 → 文件
         │        ├─ 文字/报告/方案 → .md（默认）或 .docx / .pdf
         │        ├─ 表格/数据 → .xlsx / .csv
         │        ├─ 演示 → .pptx / .pdf
         │        ├─ 代码 → 对应源文件
         │        └─ 网页/交互工具 → 单文件 .html
         └─ 不确定 → 先按最合理形态做，交付时一行说明；不问
```

## 形态选择细则

**对话回复**：问答、解释、短摘要、对附件的点评、一次性阅读的短报告。用户说"分析一下"但没说要文件 → 默认回复，除非分析结果本身是数据集。

**文件**：会被再次打开、编辑、发送、归档的内容。判据不是长度，而是"是否离开本次对话继续存在"。

**单文件 HTML**：网站、落地页、计算器、交互式说明、仪表盘原型。要求：CSS/JS 内联，无外部依赖，离线可打开。不要为"看看效果"生成一堆项目脚手架。

**表格文件**：行数超过约 20、需要排序筛选、需要公式、需要给他人继续编辑。少量对比用 Markdown 表即可。

**演示文件**：需要按页讲、需要投影、需要发给别人。单纯"总结成几点"不是演示。

**长文**：先给大纲（5–10 行），确认后再展开；用户明确说"直接写完"则不确认。分节生成，最后合并。

## 数据任务

- 不把大型结果集逐条打印到对话。
- 先落文件（csv/parquet/json），再用代码计算；对话里只给结论、口径、异常。
- 报告数字时给出口径：时间范围、去重规则、缺失值处理。
- 图表：一张图只回答一个问题；轴标签和单位必须写；不给无标题图。

## 文档与 Office 文件

| 目标 | 先加载 | 关键约束 |
|---|---|---|
| .docx / .dotx | `docx` | 新建用 docx-js；编辑走 OOXML；交付前渲染检查 |
| .pdf | `pdf` | 文本可提取时不要先转图片；表单用专用脚本 |
| .pptx / .potx | `pptx` | 内容、文件、视觉三层 QA；先查文字溢出 |
| .xlsx / .xlsm / .csv | `xlsx` | 公式不是硬编码；必须重算；零错误 |
| 提案、规格、决策文档 | `doc-coauthoring` | 先收上下文，再分节写，最后做读者测试 |

- 编辑已有文件时保持原格式，不转成别的格式再重写。
- 交付前按 `document-workflows.md` 的 QA 执行；格式细节和脚本以完整 skill 为准。
- 文件格式由结果去向决定，不由用户口头说的"文档"一词决定。

## 命名与交付

- 文件名可读：`2026-11-17-销售汇总.xlsx`，不用 `output_final_v3.xlsx`。
- 交付时一行说明：是什么、给谁、有什么已知限制。
- 不在对话里重复文件全文。
- 多个文件给一个清单，每个一行说明用途。
- 路径用代码格式，避免用户找不到。

## 三种值得先问的情况

只有三种，其余一律先做：

1. 用户指代一个你看不到的原件（"在那个表里加一行"），且格式未说明。
2. 用户要求的格式本会话无法生成（特定的在线文档、专有格式）。
3. 同一请求合理落在多种交付物上，成本高且难以重做（"做个给管理层看的东西"）。

不要用"你想要什么格式"代替判断。先做最合理的一种，交付时说明；用户不满意再改，成本通常低于一次来回。

## 常见误判

| 误判 | 后果 | 修正 |
|---|---|---|
| 把"文档"一词当成要 .docx | 生成没人要的文件 | 默认 Markdown；明确要 Office 才转 |
| 把长回答拆成十个标题 | 阅读负担 | 超过 400 字才用标题；否则段落 |
| 把数据贴在对话里 | 无法复用、容易抄错 | 落文件再算 |
| 为简单页面生成完整前端项目 | 无法直接打开 | 单文件 HTML |
| 用户说"分享"就生成网页 | 可能只需要文本 | 先判断接收方与用途 |
| 交付时复述文件内容 | 冗余 | 一行说明 + 文件 |

## 形态路由的边界

- 不假设部署有托管产物或在线文档能力；默认产出本地可打开的文件。
- 不假设有格式转换服务；需要 PDF 时用本地工具生成，并验证结果。
- 不为了"看起来专业"升级形态：能一句话说清就不要生成文件。
- 形态一旦选定，不在中途反复切换；需要换形态时说明原因并保留已生成的内容。
